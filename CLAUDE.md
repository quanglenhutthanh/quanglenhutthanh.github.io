# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A [Quarto](https://quarto.org) static site: personal portfolio/CV + a per-course knowledge base for an AI master's program. Not a software application — there is no build tooling beyond Quarto itself, no package.json/requirements.txt, no test suite. Content is written in `.qmd` (Quarto markdown) and `.md`, with Jupyter notebooks kept as-is for labs.

## Commands

```bash
quarto preview        # live-reload local preview
quarto render         # build static site into _site/
```

Requires the [Quarto CLI](https://quarto.org/docs/get-started/) installed locally. There is no lint/test command — verify changes by rendering and checking `_site/` output, or via `quarto preview`.

Deploy is automatic: pushing to `main` triggers `.github/workflows/publish.yml`, which runs `quarto render` and publishes to the `gh-pages` branch (GitHub Pages must be pointed at that branch). No manual deploy step.

## Architecture

**Site config** (`_quarto.yml`) defines the navbar, theme (`cosmo` + `styles.css`), and global HTML options (TOC, KaTeX math). This is the single source of truth for site-wide structure — check it before adding new top-level pages/nav items.

**Course structure** — each subject under `courses/<subject>/` follows a fixed convention:
- `index.qmd` — subject landing page. Frontmatter declares a Quarto `listing` block (`id: lectures`) that auto-generates a table of lectures from `lectures/*.md`, sorted by `lecture_no`. **Do not hand-write the lecture table** — add a lecture file with the right frontmatter and the listing regenerates it.
- `lectures/<slug>.md` — one file per lecture (no ordering prefix in the filename; ordering is driven entirely by the `lecture_no` frontmatter field). Required frontmatter fields: `title`, `subject`, `type: lecture`, `lecture_no`, `status` (`todo`/`reading`/`done`), `source`, `tags`, `date`. The `subject`/`type`/`lecture_no`/`status`/`tags` fields are what the listing tables key off of — missing/wrong fields silently break sorting or hide the row.
- `labs/*.ipynb` — Jupyter notebooks kept as-is (not rendered/executed by default in the workflow beyond having jupyter/nbformat available); linked manually from the subject `index.qmd`.
- `references.qmd` — a hand-maintained markdown table of papers/links per subject. Intentionally link-only — no hosted PDFs; detailed notes live in Notion (external), not in this repo.

`courses/index.qmd` has its own top-level `listing` (`contents: "*/index.qmd"`) that auto-lists every subject — adding a new subject folder with a conforming `index.qmd` is enough to have it appear, no manual registration.

**Content language**: lecture/course prose is written in Vietnamese; frontmatter keys and code stay in English. Keep new content consistent with this split.

**Assets**: global assets in `assets/` (avatar, site-wide images); per-subject images in `courses/<subject>/assets/`.

## Conventions to preserve

- Never hand-edit `_site/` — it's fully regenerated by `quarto render`/the publish workflow and is gitignored.
- When adding a lecture, match the frontmatter schema exactly (see an existing file like `courses/image-and-video-processing/lectures/color-image.md`) since the subject `index.qmd` listing depends on those fields.
- `references.qmd` files are tables only, no file hosting — add rows, don't attach documents.
